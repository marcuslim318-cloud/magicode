透过冰晶棱镜，让新功能安全发芽

上一关你有了「改坏能倒回」的底气。今天再学一道高级护身术：分身术。 把主线想象成一道白光——你不用在它上面直接改，而是从它分出一道彩光（分支）， 在副本上安全地试新功能，成了再合并回主线。这样主线永远稳稳当当， 你怎么折腾都不怕。

免费 · 纯浏览器 · 约二十分钟 · 完成即得魔力值 +450

01

第一道彩光：造一个安全的副本分支

未解锁

第一步：从主线分出一条「分身」。分身是主线的一个复制品——你在里面随便折腾，主线一点不受影响。给它起个清楚的名字，比如「试试新功能」。

  • 打开你的仓库 → Branches 标签（或直接在页面顶部找分支下拉）
  • 新建一个分支，命名为 try-new-feature（或你喜欢的名字）
  • 看到它自动切换到你新分支上——你现在在安全副本里了

✦猫头鹰为你分出一道光…副本分支建好后回来。

放猫头鹰去建分身
git checkout -b try-new-feature
示意演示 · GitHub 网页上新建分支，做的就是这样一件事
02

第二道彩光：在副本上加新功能

未解锁

现在你在这个安全的副本分支里，可以放手加新功能了——用咒语让 AI 帮你在它上面加一样新东西，Commit 上去。因为是在分身里，怎么改都不会碰坏主线。

把下面这句粘贴给你的 AI 工具： 「我在一个新分支 copy 上想给我的作品加一个新功能：【描述你想加的功能，比如：加一个点击显示/隐藏的欢迎横幅】。请帮我想想，并把需要改动的完整 index.html 全文给我。放心，我在安全的分支上，改坏了也不影响主版。」

替换、Commit——你的改动只存在于这个分支上，主线安然无恙。

✦猫头鹰在副本上种下新功能…新功能在分身上能用了后回来。

放猫头鹰去种新功能
03

第三道彩光：把彩光合并回白光

未解锁

新功能在副本上验证没问题了，就把这道彩光合并回主线白光——用 Pull Request（合并请求）：提交一个「把分支合进主线」的请求，确认合并。主线 +1，副本功成身退。

git merge try-new-feature
新功能已并入主线 · 白光更明亮
示意演示 · GitHub 网页上的 Pull Request 合并，做的就是这样一件事

合并后，如果发现还是不合适，你还有第 10 关的时光倒转兜底。现在的你对作品有绝对的掌控力。
